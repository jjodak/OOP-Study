# 객체지향프로그래밍 기말고사 문제

- 범위: 9주차 ~ 14주차
- 제한시간: 2시간 30분
- 배점: 100점
- 제출 형식: 실행 가능한 Java 소스 파일 전체
- 사용 가능 자료: 수업 시간에 작성한 예제 코드와 이미지 파일

## 시험 안내

1. `javafinalexam/src/w9`, `javafinalexam/src/w10`, `javafinalexam/src/w11`의 Swing 예제 소스를 참고하거나 일부 수정하여 사용할 수 있다.
2. `javacodes/src/w12`, `javacodes/src/w13`, `javacodes/src/w14`의 이미지, 이벤트, 그래픽, 좀비 게임 소스를 참고하거나 일부 수정하여 사용할 수 있다.
3. 최종 프로그램은 하나의 GUI 프로그램으로 실행되어야 한다.
4. 패키지와 클래스 이름은 자유롭게 정해도 되지만, 실행할 `main()` 메소드가 있는 클래스를 명확히 작성해야 한다.
5. 이미지를 불러오지 못하는 환경에서도 프로그램이 종료되지 않도록 기본 도형 또는 문자열로 대체 출력할 수 있게 한다.

## <문제> Swing 좀비 게임 - 보물 많이 획득하기 GUI 버전

수업 시간에 작성한 `ZombieGame`을 기반으로, Swing GUI에서 동작하는 보물 획득 게임을 구현하시오.

주인공은 키보드 또는 버튼으로 이동한다. 좀비는 스레드로 자동 이동한다. 보물은 화면에 하나씩 나타나며, 주인공이 보물과 충돌하면 점수가 올라가고 새로운 보물이 랜덤 위치에 생성된다. 주인공이 좀비와 충돌하면 게임이 종료된다.

## 문제 1. 화면 구성 구현 (20점)

다음 조건을 만족하는 Swing 화면을 구성하시오.

1. `JFrame`을 사용하여 게임 창을 만들고 제목을 `"Final Zombie Gem Game"`으로 설정한다. 창 크기는 자유롭게 정하되 게임 화면이 잘 보이도록 한다.
2. 전체 화면은 `BorderLayout`을 사용한다.
3. 중앙에는 `GamePanel extends JPanel`을 배치하고, 이 패널에서 주인공, 좀비, 보물, 배경을 직접 그린다.
4. 상단 또는 하단에는 다음 정보를 보여주는 `JLabel`을 배치한다.
   - 현재 점수
   - 획득한 보물 개수
   - 현재 보물 이름과 위치
   - 게임 상태: 준비, 진행 중, 승리, 게임 오버
5. 별도의 버튼 패널을 만들고 다음 버튼을 배치한다.
   - `Start`
   - `Reset`
   - `Left`
   - `Jump`
   - `Right`
6. 난이도를 선택할 수 있는 `JRadioButton` 3개를 만들고 `ButtonGroup`으로 묶는다.
   - Easy
   - Normal
   - Hard
7. 충돌 범위를 화면에 표시할지 선택하는 `JCheckBox`를 만든다.
8. 버튼, 라벨, 라디오 버튼, 체크박스 중 최소 1개 이상에는 `ImageIcon`을 활용한다.

## 문제 2. 이벤트 처리 구현 (25점)

다음 이벤트 처리를 구현하시오.

1. 키보드 이벤트
   - 오른쪽 방향키: 주인공이 오른쪽으로 이동한다.
   - 왼쪽 방향키: 주인공이 왼쪽으로 이동한다.
   - 위쪽 방향키 또는 스페이스바: 주인공이 점프한다.
   - 주인공은 게임 화면 밖으로 나가면 안 된다.
2. 버튼 이벤트
   - `Start`: 게임 스레드를 시작하고 상태를 진행 중으로 변경한다.
   - `Reset`: 점수, 보물 개수, 주인공 위치, 좀비 위치, 보물 위치를 초기화한다.
   - `Left`, `Jump`, `Right`: 방향키와 동일하게 동작한다.
3. 라디오 버튼 이벤트
   - Easy: 좀비가 느리게 움직인다.
   - Normal: 좀비가 보통 속도로 움직인다.
   - Hard: 좀비가 빠르게 움직인다.
   - 난이도를 바꾸면 상태 라벨에 현재 난이도를 표시한다.
4. 체크박스 이벤트
   - 선택하면 주인공, 좀비, 보물의 충돌 범위를 화면에 그린다.
   - 선택을 해제하면 충돌 범위를 숨긴다.
5. 마우스 이벤트
   - 게임 패널을 클릭하면 현재 보물의 위치를 클릭한 좌표로 옮긴다.
   - 클릭한 좌표를 상태 라벨에 출력한다.
6. 버튼이나 라디오 버튼을 누른 뒤에도 키보드 조작이 계속 가능하도록 포커스를 처리한다.

## 문제 3. 그래픽 게임 기능 구현 (40점)

`paintComponent(Graphics g)`와 별도 그래픽 클래스를 활용하여 게임 기능을 구현하시오.

1. 다음 클래스를 구현하거나 기존 클래스를 수정하여 사용한다.
   - `GraphicHero`: 주인공의 좌표, 방향, 점프 상태, 이동, 그리기 기능
   - `GraphicZombie`: 좀비의 좌표, 랜덤 이동, 그리기 기능
   - `GraphicGem`: 보물의 이름, 점수, 좌표, 랜덤 생성, 그리기 기능
2. 주인공은 오른쪽/왼쪽 방향에 따라 다른 이미지 또는 다른 색 도형으로 그린다.
3. 좀비는 최소 2마리 이상 생성한다.
4. 좀비는 `Thread` 또는 `Runnable`을 사용하여 자동으로 움직인다.
5. 좀비는 1초에서 2초 사이 또는 선택한 난이도에 맞는 시간 간격으로 랜덤하게 움직인다.
6. 보물 종류는 다음 3가지 중 하나로 랜덤 생성한다.
   - Diamond: 30점
   - Gold: 20점
   - Silver: 10점
7. 주인공이 보물과 충돌하면 다음 처리를 한다.
   - 점수를 올린다.
   - 획득한 보물 개수를 1 증가시킨다.
   - 상태 라벨에 `"Diamond 획득 +30점"`처럼 출력한다.
   - 새로운 보물을 랜덤 위치에 생성한다.
8. 주인공이 좀비와 충돌하면 게임을 종료하고 `"좀비에게 잡혔습니다"`를 화면에 출력한다.
9. 점수가 100점 이상이 되면 게임을 종료하고 `"보물 100점 달성"`을 화면에 출력한다.
10. `repaint()`를 적절히 호출하여 화면이 계속 갱신되게 한다.

## 문제 4. 완성도와 코드 구조 (15점)

다음 항목을 기준으로 완성도를 평가한다.

1. 프로그램이 컴파일되고 `main()`에서 정상 실행된다. (3점)
2. 클래스 역할이 적절히 분리되어 있다. (3점)
3. 상수, 필드, 메소드 이름이 기능을 이해할 수 있게 작성되어 있다. (2점)
4. 이미지 경로 오류, 게임 종료 후 키 입력, 중복 스레드 실행 등으로 프로그램이 쉽게 깨지지 않는다. (3점)
5. 게임 상태, 점수, 보물 정보가 화면에 명확히 표시된다. (2점)
6. 기존 수업 예제의 기능을 단순 복사하는 데서 끝나지 않고 하나의 게임으로 자연스럽게 통합되어 있다. (2점)

## 출제 방향 메모

중간고사는 하나의 좀비 게임에 `Gem` 클래스, 보물 획득, `Vector` 저장, 저장/이어하기 기능을 단계적으로 추가하는 실습형 문제였다. 이 기말고사 문제는 같은 방식으로 하나의 게임을 확장하되, 9주차부터 14주차까지의 Swing 화면 구성, 이벤트 처리, 컴포넌트, 직접 그리기, 이미지, 스레드를 모두 활용하도록 구성하였다.
